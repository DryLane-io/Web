Zao

Serialization at the speed of memcpy. The fastest zero-allocation encode in .NET.

0.87 ns to encode a 16-byte message. MemoryPack takes 3.11 ns. 268× faster than Protobuf on a 1,024-entity snapshot. 0 B allocated per encode. Protobuf and JSON allocate on every call. 1.4–3.6× ahead of MemoryPack, the only rival within an order of magnitude.
What it is
The piece that turns your data into bytes and back. Tag a struct and a source generator writes the code at build time. For simple types it just copies memory, so the fast path runs at the speed of memcpy.
The problem
Protobuf and JSON walk every field, allocate and encode: real CPU spent on data that is about to be thrown away. Where the layout already matches, Zao charges nothing.
For example
In the F1 replay, every telemetry sample carries a packed blob next to its numeric columns. Zao packs and unpacks those at line rate.

Only MemoryPack stays within an order of magnitude, and it still trails by 1.4 to 3.6 times. MessagePack is 4 to 60 times back. Protobuf and JSON are one to three orders behind, and they have no zero-allocation path at all.

Where Zao doesn't win. It isn't the smallest on the wire: MessagePack's varint packing beats it on small, integer-heavy messages. On decode Zao is fastest across the board and allocates less for value-type messages (72 B against 128 B on SpawnEntity), but collection-heavy messages force everyone to build the same arrays, maps and strings, so memory ties.
